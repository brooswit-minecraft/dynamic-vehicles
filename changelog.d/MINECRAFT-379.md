### Added
- Pathfinder region/circuit core (`pathfinder` package): deterministic 512x512-block region identity, Chebyshev ring enumeration, and a spatially-coherent circuit ordering, producing the designed 8/16/24/32-region circuits for levels 2-5 and an 8-checkpoint local loop for level 1 (settled 2026-10-18). A route is a pure function of origin region + level, so it is identical across villagers, retries, reload and multiplayer sessions.
- `PathfinderCheckpoint`/`PathfinderPosition`: each checkpoint is a concrete, dimension-aware position with its own finite, positive reach radius, not just "somewhere in this region".
- `PathfinderTerrainPlacer`: real, read-only terrain-safe checkpoint placement - a small bounded, deterministic search for a column with no lava underfoot, two blocks of headroom, and valid world-height bounds, falling back to the unmodified candidate only if every searched offset fails. Never modifies terrain. Routes are cached server-wide per (dimension, origin, level) by `PathfinderRouteStorage` so checkpoint coordinates stay fixed across retries/reloads/later infrastructure edits even though the placer itself isn't a pure function of world state over time.
- `PathfinderProgress`: server-authoritative, in-order checkpoint validation (dimension + proximity, not region entry) with out-of-order rejection, an overall completion time limit evaluated atomically with every reach report, and a closing leg back to the first checkpoint.
- A working vertical slice: right-click a Pathfinder villager (profession + "Route Board" workstation block/POI, reusing the shared `VillagerJobSites` helper) to start an attempt at its region/level; a coarse server tick evaluates each online player's active attempt, advances it on real movement, and grants an emerald reward (scaling with level) on completion, force-saving and clearing the attempt before paying out (narrows, documented as not eliminating, the reward-duplication crash window). Death fails the attempt outright. Persisted server-wide via `PathfinderAttemptStorage`/`PathfinderRouteStorage` (`SavedData`), survives reconnect/reload/restart. A minimal HUD overlay shows next-checkpoint direction and remaining time (or cross-dimension guidance instead of a meaningless arrow when the player isn't in the checkpoint's own dimension), mirroring the Dispatcher's own HUD pattern.
- `PathfinderVillagerLevel`/`PathfinderVillagerProgress`: a Pathfinder villager's own level is tracked on its persistent data, advancing only via actual circuit completions at that villager (3 by default) - deliberately NOT `VillagerData`'s trade-based level, which `setProfession` preserves across a profession change and would otherwise let a villager trade-leveled under any other profession instantly unlock high Pathfinder levels.
- `PathfinderServerConfig`: timer, reward, reach-radius and level-advancement-threshold values are now a real `ModConfigSpec` (following `DispatcherOfferConfig`'s pattern), not plain constants. Changing a value never affects an attempt already in progress - it's snapshotted into that attempt's own record at start time.
- Block/profession textures are an explicit placeholder (the Dispatcher's own board/profession art, reused) pending real art.
