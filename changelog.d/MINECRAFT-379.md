### Added
- Pathfinder region/circuit core (`pathfinder` package): deterministic 512x512-block region identity, Chebyshev ring enumeration, and a spatially-coherent circuit ordering, producing the designed 8/16/24/32-region circuits for levels 2-5 and an 8-checkpoint local loop for level 1 (settled 2026-10-18). A route is a pure function of origin region + level, so it is identical across villagers, retries, reload and multiplayer sessions.
- `PathfinderCheckpoint`/`PathfinderPosition`: each checkpoint is a concrete, dimension-aware position; the reach radius to check against is a parameter at check time, not stored on the checkpoint, so a config change takes effect immediately for every in-progress and already-cached route.
- `PathfinderTerrainPlacer`: real, read-only terrain-safe checkpoint placement - a small bounded, deterministic search for a column with no lava underfoot, standable footing, two blocks of headroom, and valid world-height bounds. Fails closed (returns no checkpoint) rather than falling back to an unsafe candidate when every searched offset fails; `PathfinderRouteGenerator`/`PathfinderRouteStorage` propagate that as a failed, uncached route generation, and `PathfinderAttempts` reports it to the player as a retryable "no safe route" message instead of starting an invalid attempt. Never modifies terrain. Successful routes are cached server-wide per (dimension, origin, level) by `PathfinderRouteStorage` so checkpoint coordinates stay fixed across retries/reloads/later infrastructure edits.
- `PathfinderProgress`: server-authoritative, in-order checkpoint validation (dimension + proximity, not region entry) with out-of-order rejection, an overall completion time limit evaluated atomically with every reach report, and a closing leg back to the first checkpoint.
- A working vertical slice: right-click a Pathfinder villager (profession + "Route Board" workstation block/POI, reusing the shared `VillagerJobSites` helper) to start an attempt at its region/level; a coarse server tick evaluates each online, alive player's active attempt, advances it on real movement, and grants an emerald reward (scaling with level) on completion. Completion/expiry clear the attempt and force a real, blocking disk-save (`IOUtilities#waitUntilIOWorkerComplete`) BEFORE paying out, so a crash afterward cannot reload the old record and pay again. Death (the real `LivingDeathEvent`, not deferred to respawn) fails the attempt outright; `onServerTick` also skips evaluating any player who isn't alive, as defense in depth. Persisted server-wide via `PathfinderAttemptStorage`/`PathfinderRouteStorage` (`SavedData`), survives reconnect/reload/restart - verified against a real save/load NBT round trip, including a reload-then-expire case proving the deadline is measured in game ticks, never wall-clock time. A minimal HUD overlay shows next-checkpoint direction and remaining time (or cross-dimension guidance instead of a meaningless arrow when the player isn't in the checkpoint's own dimension), mirroring the Dispatcher's own HUD pattern.
- `PathfinderVillagerLevel`/`PathfinderVillagerProgress`/`PathfinderVillagerProgressStorage`: a Pathfinder villager's own level, tracked server-wide by villager UUID (independent of whether that villager's entity is currently loaded - a circuit routinely completes regions away from its own villager), advances only via actual circuit completions at that villager (3 by default). Deliberately NOT `VillagerData`'s trade-based level, which `setProfession` preserves across a profession change and would otherwise let a villager trade-leveled under any other profession instantly unlock high Pathfinder levels.
- `PathfinderServerConfig`: timer, reward, reach-radius and level-advancement-threshold values are now a real `ModConfigSpec` (following `DispatcherOfferConfig`'s pattern), not plain constants. The timer is genuinely snapshotted into an attempt's own record at start time; reach radius, reward and the level threshold are read fresh at the moment they're used, so a config change takes effect immediately rather than being frozen at whatever it was when a route/attempt first came into existence.
- Block/profession textures are an explicit placeholder (the Dispatcher's own board/profession art, reused) pending real art.
